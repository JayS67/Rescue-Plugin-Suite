# Rescue Plugin Suite v15.1.2

This release hardens WordPress updates, removes misleading controls and keeps widget
presentation from changing the host website.

- Preserve upstream WordPress errors during source selection instead of triggering a
  fatal object-to-string conversion. Reject incomplete packages before replacing the
  installed copy. Keep the installed plugin directory/basename when updating a renamed
  installation. Never load replacement plugin code inside the old update request.
- Use WordPress's native auto-update preference, including its Plugins-screen toggle.
  Expose stable/beta release preferences and cache failed update checks briefly to avoid
  repeated slow remote requests.
- Add transparent outer widget surfaces and separate title/subtitle/footer switches in
  General → Shared styling. Retain paw patterns, including stationary patterns with
  reduced motion. Keep dialogs and animal profile pages opaque/readable.
- Scope utility CSS, defaults and animations to suite-owned DOM. Do not enqueue payment
  assets on unrelated pages. Restore pre-existing page scroll styles when dialogs close.
- Remove visible no-op controls (unused raw layout/schema/species controls, decorative
  payment fields and adopted badge options). Keep supported colours, columns, spacing,
  typography, card parts, feeds, presets and provider settings; preserve legacy saved keys.
- Preserve unsent settings when saving a subtab. Keep multiline field maps and layout
  order intact rather than applying the generic text sanitizer a second time.
- Honour Gift Aid enablement, consent wording, required consent and storage settings.
  Preserve the accepted declaration text. Respect a donor declining fee recovery.
- Turning animal modals off now opens the crawlable profile instead of leaving dead
  buttons. Ordinary host pages with WordPress `cat` parameters keep their own metadata.

## Validation

The tests use a disposable WordPress site and fixture provider data. They cover native
manual and automatic update lifecycles, fresh-request bootstrap, preservation of renamed
plugin directories, rejected/incomplete packages, native auto-update preferences, partial
settings saves, rendered settings accessibility, SEO regressions, payment settings logic,
mobile/desktop widget behaviour, transparent/text options and host-style/scroll isolation.
Live payment gateways and live shelter form submissions were not exercised. These checks
cannot establish compatibility with every WordPress theme or third-party extension.

## Installing from an older crashing updater

If the installed version cannot complete its own update, use WordPress Plugins → Add
New → Upload Plugin with the canonical ZIP and choose to replace the installed version.
The fixed updater runs only after the new files are installed. Preserve a site backup
and use the documented WordPress recovery process if the old installation cannot load.

Package name: `rescue-plugin-suite-v15.1.2.zip`; archive root: `rescue-plugin-suite/`.
The GitHub release must remain a **draft** until reviewed. Do not push a version tag
before creating the draft: the repository's tag workflow publishes release assets.
